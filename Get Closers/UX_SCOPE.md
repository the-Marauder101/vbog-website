# Pravah Sections and Modal Inventory

This inventory controls interface scope. Version labels prevent an attractive
shell from being mistaken for completed production behavior.

## Sections

| Section | Primary content | Activation |
|---|---|---|
| Overview | headline KPIs, attention queue, operating flow | shell V0; live V1 |
| Training & placements | incoming placements, cohort, checkpoints, decisions | V1 |
| Active closers | roster, targets, results, risks, recovery plans | V1 |
| Clients | portfolio health, check-ins, issues, actions | V1 |
| Reports | structured updates, WhatsApp output, history | prototype V0; live V1 |
| Data & connections | source state, imports, reconciliation | shell V0; live V2/V5 |
| KPI scorecards | weighted KRAs, KPI evidence, thresholds | V3 |
| Leads & revenue | leads, activity, pipeline, sales, payments | V4 |
| Client workspace | isolated dashboards and native CRM | V6 |
| Settings | users, roles, taxonomies, templates, mappings | V1 onward |

## V0 modal

### Paste WhatsApp report

Purpose: preserve the current team habit while proving structured capture.

States:

1. paste or use example;
2. parse common aliases;
3. show recognized and unstructured lines;
4. require closer name;
5. preview normalized fields;
6. save local draft;
7. copy a WhatsApp-ready summary from Reports.

## V1 modals

- Add/edit client
- Record incoming placement
- Start training
- Record training checkpoint
- Complete or extend training
- Add weekly closer report
- Add client check-in
- Create corrective action
- Update target
- End placement
- View source context (read-only Vyom/Nikash links)

## V2 modals

- Link candidate identity
- Resolve integration conflict
- Retry failed event
- Review milestone writeback

## V3 modals

- Configure KPI target and threshold
- Submit KPI evidence
- Review and lock scorecard
- Add pattern-recognition case

## V4–V6 modals

- Add/edit lead
- Log activity
- Move pipeline stage
- Record sale
- Record payment/refund/cancellation
- Import source file
- Map columns and stages
- Repair rejected rows
- Invite client or closer
- Configure client permissions

Every destructive or cross-system action requires an explicit confirmation,
named target, actor, timestamp, and audit entry.
